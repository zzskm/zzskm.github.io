## 1. 목표와 결정 사항

**사용자가 1초 내에 ① 버스 도착 예상 HH:mm ② 남은 분 ③ 현재 출발 행동을 파악**하게 한다. 기존의 긴 설명·배지·복수 카드·타임라인이 첫 화면에서 주요 정보를 밀어내는 문제를 해소한다.

수용할 시안 요소:
- 상단의 작고 명확한 노선·정류장 헤더, 상태 점 + 최종 업데이트, 새로고침.
- 큰 도착 시각과 남은 시간/정류장 거리. 단일 행동 카드(여유/출발 권장/늦음/확인 불가).
- 카드에는 출발 권장 **절대시각**과 짧은 **상대시간**, 계산 근거로 도보·추가 여유.
- 다음 버스 한 줄, 접이식 상세, 모바일 설정 바텀시트, 절제된 명암/상태 색.
- 데이터 지연/오류/차량 변경은 도착 본문과 구별되는 명시적 상태 안내.

그대로 복제하지 않을 시안 요소:
- 시안의 **146번·22009·강남역**을 실제 서비스에 하드코딩하지 않는다. 기존 3100번·07511·방면·실제 데이터/설정은 보존한다.
- `7분 남음`만으로 `지금 출발`을 결정하거나 `API ETA - 도보 - 여유`로 기존 보수적 안전 출발 모델을 덮어쓰지 않는다.
- `no_bus` 또는 갱신 실패를 `운행 종료`로, ETA 경과를 `실제 버스 통과`로 단정하지 않는다. **다음 날 첫차 시각**은 제공 데이터가 없으면 표시하지 않는다.
- 시안의 `11:09 · 약 10분 후`처럼 오래된 절대시각으로 **진행형 실시간 카운트다운**을 만들어 보여주지 않는다.
- React/v0 앱을 제품에 통째로 도입하지 않는다. 현재 GitHub Pages 정적 HTML/CSS/JS 및 통합 대시보드 호환성을 유지한다.

**불변 조건:** `alarm.js`의 안전 보정·발화 시각·알림 원장, `alert-runtime.js`의 소리/OS 알림/중복 방지, 공개 JSON/CSV 스키마, 수집 빈도·API 호출 수, localStorage 설정 키를 보존한다. 일반 시각 알람과 타이머는 복구하지 않는다. 화면 문구는 알림 전달 보장을 암시하지 않는다.

## 2. 권장 정보 구조

모바일 360~430px, 접히지 않은 첫 화면의 우선순위:

```text
3100  유라코퍼레이션.SK케미칼 · 07511      [설정]
우림아파트 방면
● 최근 정상 조회 18:00 · 실시간 가능       [새로고침]

도착 예정 (공공 API)
        18:20              ← 가장 큰 요소
20분 후 · 4정거장 전         ← 시점/거리(제공될 때만)

[상태별 단일 행동 카드]
출발까지 8분 남음 / 지금 출발 / 권장 시각 지남 / 판단 보류
출발 권장 18:08 · 도보 5분 + 여유 1분
(필요 시 보수적 조기 도착 근거 안내)

다음 3100번        18:30 · 30분 후
[예측 정보·알림 상세 펼치기]
```

- 헤더에는 중복된 노선·정류장 정보를 한 번만 표기. 실제 `status.json`이 제공하지 않는 위치·좌석은 생략/미확인.
- 크게 표시하는 ETA는 오직 **현재 유효한 API 예측**(`view.apiAtMs`). 안전 도착 기준(`view.safeAtMs`)·보정 예상(`view.correctedAtMs`)은 원본 시각과 혼동되지 않게 상세에서 구분.
- 안전 출발 판단은 기존 `BD.buildView`의 `departureAtMs`, `state`, `uncertain`, `ageSec`를 사용. 서로 다른 위치에서 새 공식을 계산하지 않는다.
- 카드 색은 **여유=저채도 녹색, 권장 시점=황색, 권장 경과=적색, 신뢰 불가=중립 회색**으로 제한. 색 외에 문구/아이콘 필수. 오버듀 상태는 실제 탑승 실패를 뜻하지 않음.
- 다음 버스는 `decisionSnap.next`가 유효할 때만 도착 HH:mm/상대시간 표시. 다음 차량의 선택/제외 등 기존 정책에 따른 예외는 그대로 유지.
- 알림 켜짐·권한·소리·N분 전 설정·시간대·사전 준비 알림·타임라인·그래프·운행 기록·수집 정보는 **접힌 상세**로 이동. 현재 기능은 제거하지 않는다.
- 상단 `새로고침`은 기존 요청·중복 방지·세대 검사·오류 피드백을 재사용. 진짜 수집/게시 시각과 브라우저 요청 시각을 구별한다.
- `시나리오` 플로팅 버튼은 v0 디자인 검증용이다. 프로덕션에 추가하지 않는다.

## 3. 상태별 명세 (UI 상태와 근거의 구분)

| 상황 | 첫 화면 표현 | 표시·행동 제약 |
| --- | --- | --- |
| 정상·여유 (`waiting`) | API HH:mm, 남은 분, `출발까지 N분`, 출발 권장 시각 | 보수적 기준이 이미 지났다면 API ETA가 멀어도 여유로 표시하지 않음 |
| 출발 권장 시각 (`due`) | `지금 출발 권장` | 안전 기준에서 계산한 실제 경계 적용. 시각/남은 시간 반올림 일치 |
| 권장 시각 경과 (`overdue`) | `출발 권장 시각 지남`, N분 경과 | `버스를 놓침` 확정 금지. API ETA가 미래라면 계속 참고하되 위험 표시 |
| ETA 급변 | `도착 예상 앞당겨짐/늦춰짐` 별도 짧은 배너 | 같은 차량·운행, **서로 다른 실제 관측** 비교. 초 단위 시간 감소나 설정 변경은 ETA 변동 아님 |
| 차량 제외 (`skipped`) | `이번 차량 제외됨 · 다음 차량 확인 중` | 제외 차량의 출발 권고를 재사용하지 않음. 되돌리기 유지 |
| API ETA 경과 (`elapsed`) | `도착 예정 시각 지남 · 통과 미확인` | 실제 통과 확정 금지. 다음 차량으로 바꿀 때 식별·조건 검증 |
| `no_bus` | `현재 조회에서 차량 확인 안 됨` | 운행 종료/미운행 확정 금지. 유효한 다음 차량도 없으면 ETA `--:--` |
| 3분 초과·불확실 (`unavailable`) | `최신 정보가 없어 출발 판단 보류` | 큰 실시간 HH:mm·카운트다운 숨김. 마지막 확인 정보는 별도 참고 기록에만 |
| 기존 예약 경고 (`reserved`) | `최신 정보 없음 · 마지막 자료 기준 예약 경고` | 과거 예약은 오직 기존 엔진 정책으로 유지. 현재 출발 권장과 혼동 금지 |
| 조회 오류/브라우저 연결 실패 | `정보 갱신 실패`, 마지막 정상 수집 시각·재시도 | 마지막 정상 수집 시각을 새로운 현재 수집 시각처럼 갱신하지 않음 |
| 휴일·수집 시간 외 (`off`) | `수집 시간 외` 또는 `휴일 · 수집하지 않음` | `운행 종료`, `내일 첫차 HH:mm` 같은 검증 불가 문구 금지 |
| 다음 차량 확보 | 새 대상 차량 ETA와 출발 판단 동기화 | 주 차량과 후속 차량의 도착 시간·알림 대상·시각 비교가 섞이지 않도록 함 |

시간 기준:
- 절대시각 HH:mm은 한국 시각(KST). 상대시간은 **같은 `nowMs` 값**을 입력받아 계산한다.
- 분 단위 반올림(`ceil/floor`), 1분 미만, 0초, 1분 미만 경과를 순수 표시 함수에서 정의해 테스트한다. 반올림 결과와 행동 상태가 상충하지 않아야 한다.
- `공공 API ETA`와 `출발 권장` 사이의 차이가 크면 짧은 `조기 도착 대비를 반영했습니다` 설명과 펼침 근거를 제공한다. 모델을 95% 확실성처럼 표현하지 않는다.
- `실시간` 문구는 브라우저가 초 단위로 렌더링된다는 의미가 아니라 **유효한 최신 차량 관측**이 있다는 의미로만 사용한다. 3분 초과는 기존 안전 기준과 일치시킨다.

## 4. 단계별 구현 (작업 단위와 완료 조건)

### 0단계 — 표시 계약 및 회귀 기준 동결 (P0)

**파일:** `bus-arrival/dashboard.js`, `tests/bus_dashboard.test.mjs`, `tests/bus_safety.test.mjs`.

- 현행 `BA.assessStatus(...,{maxAgeMin:3,safetyMode:true})`와 `BD.buildView` 입력/출력의 상태 의미 문서화.
- 화면용 순수 `buildPresentation`(가칭) 함수를 추가하되 **시간 예측·알림 스케줄을 새로 계산하지 않음**. 노출 ETA, 행동 문구, 보조 메타, 정보 신뢰도, 시각 변화·차량 교체·상세 데이터의 표시 허용 여부를 통일.
- 현재 시각·차량·관측·보수적 안전 시각을 고정한 테스트 fixture 작성. 3절 상태 조합 및 엣지 케이스 테스트.
- **완료:** 유효하지 않은 데이터로 활성 ETA/행동 카드를 생성하지 않고, `alarm.js`의 동작 결과가 변경되지 않음.

### 1단계 — 모바일 핵심 화면 교체 (P0)

**파일:** `bus-arrival/index.html`(HTML/CSS), `bus-arrival/app.js`의 `paint()`/화면 갱신 연결, 필요하면 별도 CSS 파일.

- 기존 `#hero` 상단에 노선/정류장·상태·ETA·출발 카드·다음 차를 재배치. 큰 HH:mm, 남은 분, 정류장 거리, 권장 시각은 일관된 뷰 모델에서 받음.
- 작은 단색 배경을 기본으로 두고 큰 상태 배경은 행동 카드 하나만 사용. 상태 배지·동일 설명 반복·다수 핵심 카드의 시각적 경쟁 제거.
- 기존 DOM ID를 가능한 재사용하고 변경 시 연계된 이벤트/접근성/정적 테스트를 같이 갱신. 실제 기능을 삭제해 단순히 테스트를 통과시키지 않음.
- 도착 시각 유효성, 새 자료 반영·동일 자료·실패, 다크모드, 360/390/430px 헤더 줄바꿈을 확인.
- **완료:** 첫 뷰포트(390×844 기준)에 노선·유효한 ETA·남은 분·권장 행동·다음 차량 정보가 순서대로 보이고, 긴 기술 설명은 기본 접힘.

### 2단계 — 설정과 보조 정보 재배치 (P1)

**파일:** `bus-arrival/index.html`, `app.js`, `alert-runtime.js`는 **행동 보존 검증 위주**.

- 스크린샷처럼 모바일의 `도보/추가 여유/버스 알림/알림 시점/테마` 설정을 **바텀시트**로 노출. 데스크톱은 적합한 다이얼로그/패널. 가능하면 기존 `#walk`, `#safety-margin`, `#alarm-chips` 설정 요소와 검증/저장 루틴을 한 벌만 사용.
- 수동 테마 선택은 시안의 선택사항이다. 넣는다면 기존 시스템 선호 기본값과 로컬 저장·대시보드 Shadow DOM 상속을 함께 검증. 기능이 불안정하면 시스템 테마만 유지.
- 알림 시간대·과거 운행 사전 알림·OS 권한/소리·알림 테스트는 고급 설정으로 보존하고 알림 활성화/권한/실제 발화 가능 여부를 구분.
- 바텀시트의 닫기·뒤로가기/ESC(지원 환경)·포커스 복귀·스크롤 잠금·접근성 레이블·보이는 설정값 즉시 갱신을 확인.
- 타임라인·예측 그래프·최근 기록·수집 상태는 접이식 섹션. 상세 이력을 기본 화면에서 길게 나열하지 않음.
- **완료:** 설정 변경 시 즉시 **같은 출발 권장 시각**이 카드/상세/알림 미리보기에 반영되고 기존 저장 키 및 원장 유지.

### 3단계 — 신뢰도/이벤트 상태 및 다음 차량 연결 (P0/P1)

**파일:** `bus-arrival/dashboard.js`, `app.js`, `tests/bus_dashboard.test.mjs`, `tests/test_bus_safety_browser.py`.

- 3절의 12개 상태를 우선순위에 따라 한 가지 지배적인 메시지로 통합. 오류 배너와 본문이 서로 반대 의미를 내지 않게 함.
- 새로고침 실패에서 마지막 정상 정보를 수집 시각과 분리하고, 시각 변화 배너는 동일 차량·동일 운행만 비교.
- 현재 차량 종료/미확인/제외 후 다음 차량 제시 여부는 **기존 식별 가능한 후속 차량**만을 사용. 시안처럼 `버스가 지나갔어요` 문구를 확정적으로 사용하지 않음.

## 5. 수용 테스트 (필수 시나리오)

1. **정상**: ETA HH:mm/남은 분/정거장 수/출발까지 N분/권장 HH:mm/다음 버스가 한 번에 보인다.
2. **안전 기준 우선**: API ETA가 12분 뒤여도 보수적 안전 출발이 지금 또는 과거라면 `여유`로 표시하지 않는다.
3. **경계**: 출발 권장 시각 1초 전 → 정시 → 1초 후; 분 반올림과 색·문구가 모순되지 않는다.
4. **ETA 변경**: 서로 다른 정상 관측으로 7분 앞당겨지면 변화량 표시. 단순 매초 감소·도보 변경에는 표시 금지.
5. **데이터 지연**: 유효 기간 초과 후 큰 실시간 ETA/남은 분 숨김; 과거 예약 경고는 기존 정책에 한해 구분.
6. **오류**: API 실패/네트워크 실패/로딩 실패 시 과거 시각의 새로고침 위장 금지. 재시도로 정상 회복.
7. **차량 미확인**: `no_bus`만으로 미운행/운행 종료/첫차 시각 확정 금지.
8. **차량 교체/제외**: 상단 도착·출발 안내·다음 버스·알림 대상의 차량 혼선 없음; 제외 되돌리기.
9. **정책 보존**: N분 리드·시간대·과거 운행 사전 알림·실제 알림 발화·중복 방지·탭 복귀 유지.
10. **설정/내장형**: 설정 변경·재방문·다중 탭 적용, 통합 대시보드 카드, 다크/확대/키보드/모바일 가독성 검증.

## 6. 범위 제외 및 구현 리스크

- **공개 수집기/공유 API 키의 추가 호출**, 모델 변경, 실시간 푸시/PWA, 새 경로 검색, 확정 첫차/막차 시각 제공, 일반 알람/타이머 복구는 범위 밖. 개인 키를 사용하는 선택적 직접 갱신은 별도 8절의 후속 단계로 관리한다.
- 우선순위가 높은 위험: **UI 임의 계산으로 안전 발화 시각과 화면 권장이 불일치**, 오래된 자료를 생생한 ETA로 표현, 차량 변경 때 다른 운행의 예측 혼입, 내장 Shadow DOM에서 스타일·설정 바텀시트가 깨짐.

- 기존 보고서 `UI_UX.md`는 과거 구현 기록으로 보존하고 이 파일을 **다음 구현의 기준 계획**으로 사용한다.

## 8. 개인 API 키를 통한 선택적 추가 갱신 (후속 단계, P1 / **미구현**)

### 8.1. 목적과 현재 상태

- 기본 서비스는 `GitHub Actions 수집 → status.json 게시 → 브라우저 60초 재조회` 구조. 브라우저의 **새로고침은 API를 재호출하지 않으며**, 배포된 `status.json`만 다시 읽는다.
- 개인이 **경기도 버스도착정보 OpenAPI의 유효한 서비스키**를 가진 경우에만, 본인 브라우저에서 별도로 조회해 화면의 ETA를 더 최근 값으로 보완할 수 있도록 한다.
- 기존 백엔드 수집 시간·공개 키 호출량·GitHub Pages 게시 주기를 **변경하지 않는다**. 사용자마다 가져온 개인 관측은 공유 서버/CSV/학습 자료에 업로드하지 않는다.
- 공식 호출: `https://apis.data.go.kr/6410000/busarrivalservice/v2/getBusArrivalItemv2`. 기존 수집 코드의 `STATION_ID=206000565`, `TARGET_ROUTE_ID=204000170`, `STA_ORDER=6`이 검증된 출발점이다. 해당 값은 배포된 수집기 설정을 기준으로 유지·검증하며 목업의 146번을 섞지 않는다.

### 8.2. 선행 기술 게이트: 브라우저 CORS

1. `https://zzskm.github.io`에서 본인의 키로 **GET 요청이 브라우저 CORS 정책상 허용되는지** 개발자 도구의 Network/콘솔로 검증. 응답 HTTP, `Access-Control-Allow-Origin`, 허용 메서드, JSON/XML body를 기록한다. **현재 CORS 허용은 검증되지 않았으므로 직접 호출 가능하다고 단정 금지**.
2. 공식 API 요청 필드는 `serviceKey`, `stationId`, `routeId`, `staOrder`, `format`. 우선 `format=xml`의 기존 수집기와 동등한 파서를 작성. 인증 오류·정상 no-bus·예측 필드 누락을 구분한다.
3. **CORS 허용 시** BYOK(Bring Your Own Key) 브라우저 직접 호출 구현. **CORS 차단 시** 정적 사이트 단독 우회 불가: 사용자가 소유·배포하고 개인키를 보관하는 Cloudflare Worker 또는 로컬 보조 서비스 선택지를 별도 설계/배포하며, 외부 공용 프록시에 키 전달을 자동화하지 않는다. CORS 우회 목적으로 타사 프록시나 키를 URL 경로/리퍼러에 전송하지 않는다.
4. 사용자의 키 없는 환경에서도 동일한 기본 서비스가 완전히 동작해야 한다. 기술 게이트 실패 시 **기능 비활성 안내만 표시**하고 구현/출시를 강행하지 않는다.

### 8.3. UI 동작과 호출 정책

- 설정 바텀시트의 **고급 설정**에 `개인 API 키로 추가 갱신` 섹션. 기본은 꺼짐. 키 입력(type=password), 연결 테스트, 활성화 토글, 제거 버튼, 소스 상태. 오류 메시지에 키·전체 요청 URL·응답 원문을 포함하지 않는다.
- 키는 기본적으로 **페이지 메모리에서만 사용**. 새로고침/재방문까지 유지하고 싶을 때만 사용자의 명시적 선택으로 이 브라우저 저장소에 보관할 수 있으나, JS에서 읽을 수 있는 `localStorage`는 **안전한 비밀 저장소가 아님**을 경고한다. URL 쿼리, Git, CI 로그, Telemetry, 페이지 HTML, 공개 `status.json` 등에 저장 금지.
- 활성화한 탭이 **화면에 보이는 동안** 60초를 기본 최소 간격으로 1회/회 조회(우선 1정류장·1노선). 닫힌/숨겨진 탭에서 개인 키 추가 호출 중단. 반복 수동 새로고침도 쿨다운 적용. API가 자체 데이터를 2분 단위로 갱신할 수 있으므로 **추가 HTTP 호출 횟수와 신규 데이터 발견 횟수를 구별**한다.
- 호출 중복 합류(Promise dedupe), AbortController 10초 타임아웃, 응답 세대/관측 시각 역전 방지. HTTP 401/403, 인증 실패, 할당량 초과, 네트워크 오류는 자동 재시도 폭주 방지(백오프/일시 중단). 하루 한도는 키/계정별 정책을 기준으로 사용자에게 안내하고 **무제한 호출 금지**.
- 공개 `status.json`은 계속 읽고 **직접 API의 실패 또는 키 제거 시 공개 데이터로 복귀**. 단, 돌아온 공개 응답이 오래됐으면 실시간으로 위장하지 않는다.
- 상태 문자열 예: `직접 조회 · 18:03 확인`, `공개 수집 · 18:01 관측`, `직접 조회 실패 · 공개 데이터 사용 중`. 서버 `queryTime`과 브라우저 수신시간을 구분하며, 둘 다 실측 버스 도착시간은 아니다.

### 8.4. 안전 출발 및 알림과의 데이터 결합 (**필수 설계 결정**)

- 원시 API가 제공하는 것: 차량 ID, 현재/다음 버스 ETA·정류장 거리·좌석 등의 **관측**. 기존 공개 `status.json`의 `safety.safe_arrival_ts`는 해당 `safety.observation_ts`에 대해서만 계산된 **시점 종속 보정**이다.
- 직접 API 관측의 `last_poll`만 최신 시각으로 바꾼 뒤, 예전 `safety` 필드를 복사해 붙이는 방식 **금지**. 기존 `BusAlarm.assessStatus`도 `safety.observation_ts === last_poll`을 확인하고, 맞지 않으면 **고정 11분 보수 여유**로 전환한다. 직접 갱신 시마다 몰래 출발 기준을 바꾸면 UI 행동/알림이 크게 흔들릴 수 있다.
- **초기 권장 범위는 직접 조회로 ETA/정거장 수/다음 차량/출처만 추가 갱신**하고, **공개 모델에 기반한 출발 권장·알림 예약은 기존 공개 관측에 귀속**시키는 방식. 직접 ETA가 더 최신이지만 안전 보정을 계산하지 못하는 동안은 `출발 안내는 공개 관측 기준` 또는 `최신 ETA와 출발 판단 기준이 다름`을 명확히 보여주고 **신뢰할 수 없는 실시간 출발 안내를 만들지 않는다**.
- 실시간 직접 관측을 실제 **출발 판단·알림 발화에도 반영**하는 확장 단계는, 과거 운행 모델을 유효하게 재계산할 수 있는 입력/버전을 제공하거나, 기존 엔진의 **명시적 고정 보수 여유(11분)** 정책을 수용한 뒤 별도 테스트와 사용자 안내를 갖춰 진행. 같은 차량/운행의 식별, 원장 중복 방지, 상태 교체/새 운행 경계가 검증되지 않으면 활성화하지 않는다.
- `no_bus`, API 오류, 직접/공개 소스 간 시간 역전, 직접 차량 A/공개 차량 B 등 충돌에서는 **그럴듯한 데이터 한 건으로 상태를 덮어쓰지 않음**. 출처별 관측을 독립 보존하고 최신성·식별 가능성으로 채택. 알림이 실제로 울린 시각은 하나의 원장으로 보존한다.

### 8.6. 완료 기준

- 키 없음/비활성 상태: **현재와 동일한 공개 버스 도착 화면 및 알림**. 추가 외부 API 호출 0건.
- 키 설정 + CORS 허용 + 정상 API: 보이는 탭에서 일정 간격의 직접 갱신, 표시 출처·수집/수신 시각 구분, 다음 차·ETA 표시. 쿨다운·중복 호출 제한.
- CORS 차단: 사용자에게 이유와 별도 개인 프록시 필요 안내. **공용 익명 CORS 프록시 사용 금지**.
- API 실패/할당량 초과: 무한 재시도 없음, 공개 데이터가 유효할 때 복귀, 오래되면 판단 보류.
- 직접 API 응답·오류·주소·설정/로그/스냅샷/스크린샷·서비스 Worker의 공개 코드에서 키 유출 없음.
- 출처가 달라진 ETA와 안전 출발 시각의 혼동·잘못된 차량 대상 알림·기존 중복 발화 원장 손상 없음. 기존 정적/Node/Playwright 테스트 전체 통과.

> **실행 순서:** v0 화면 재설계 0~4단계 중 표시 계약/설정 구조를 먼저 마련하고, 8.2의 CORS 실험을 독립적으로 수행한다. CORS 결과에 따라 8단계를 브라우저 직접 호출 구현 또는 사용자가 소유한 보조 서비스 설계로 분기한다. 이 문서는 계획만 변경하며 개인 API 키를 요청·전송·저장하지 않는다.
