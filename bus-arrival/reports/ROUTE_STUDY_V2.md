# 07511 연관 노선 분석 v2 (탐색 전용)

## 범위

`analyze_route_signals_v2.py`는 **기존 파일만 읽는다**. 정류장 전체 노선 `route_signal_log.csv`, 3100 조회 `predict_log.csv`, 3100 종료 `arrival_log.csv`로 `reports/route-study-v2.json`을 만든다. **API 추가 호출 0회, 3100 알림·안전 모델 변경 0건**. 기존 `related-routes.json`과 구형 지표도 유지한다.

## v1 대비

- 다른 노선의 차량 ID/방향/날짜마다 **예상 10분 이내로 처음 발견된 시점 1건**만 사용한다. 2순위 차량과 반복 조회를 별도 독립 운행으로 세지 않는다.
- 다른 노선 ETA 시점부터 20분 내에 3100 종료 추정치가 있는지를 양성과 음성으로 함께 기록한다. 추적 구간이 충분히 연속적이지 않으면 **음성으로 세지 않고 censored** 처리한다. 180초 넘는 데이터 공백, 수집 구간 밖의 판정 기간도 제외한다.
- 07511 **같은 API 응답 시각**의 3100 및 후보 노선 ETA를 비교한다. 그 시점에 3100 ETA가 나타나지 않았던 사례를 분리한다. 두 ETA 간 격차는 실제 선후 도착 시간의 근거가 아니다.
- **관측 날짜 전체를 기준으로 앞 60% 학습, 뒤 40% 검증**한다(최소 10일, 학습 5일, 검증 3일). 검증 날짜의 버스 종료 정보로 시간대 기준선을 학습하지 않는다. 학습 날짜의 30분 시간 구간별 목표 운행 발생률을 수집일당 동일 가중치로 계산하고, 검증 사례의 후보 신호 발생률과 비교한다. 유효 검증 사례 10건 이상일 때만 수치를 낸다.
- `eligible_for_alert_use=false`는 표본이 충분해져도 **항상** 유지한다. 실제 도착 시각과 알림 전송 이력이 없기 때문이다.

## 해석 제한

이 분석에서 사용한 3100 종료 시점은 API의 예측과 차량 소실로부터 파생된 **실측이 아닌 대리 정답**이다. 6011을 포함한 노선의 선행성·성능 개선은 아직 입증되지 않았다. 이 보고서의 `proxy_hit_rate`는 실제 도착 예측 확률도, 놓칠 위험도 아니다. 여러 차량/날짜의 상관과 관측 편향이 있으며, 검증 표본이 증가해도 P05 안전 출발 보정에 자동 연결하지 않는다. 일부 과거 로그는 도착 구간의 양 끝이 없어 추정 시점을 점으로 취급한다. 이 제한은 별도의 실제 도착 기록으로만 해결할 수 있다.

실제 성능 평가를 하려면 사용자 동의 하에 실제 정류장 도착·탑승 확인 시각과 이벤트 시계 오차를 별도로 수집해야 한다. API 조회 → 게시 커밋 → Pages 실제 반영 → 브라우저 수신 → OS 알림은 서로 다른 시각으로 계측한다. Git commit 시각을 Pages 도달 시각으로 대체하지 않는다. 본 변경에서는 개인정보 수집·외부 전송 기능을 추가하지 않는다.
