# 출발 판단 중심 UI·UX 개선

2026-10-20. 출발 판단 → 알림 준비 → 차량·최신성 → 간단 타임라인 → 상세·설정 순서로 화면을 정리했다. 한국 시각을 사용한다. 예측·안전 보정 및 알림 발화 판단은 기존 `alarm.js`와 수집기에 남기고, 공개 CSV/JSON·원본 로그·설정 키와 중복 발화 원장을 보존했다.

## 출발 판단과 표시 대상

- 권장 출발 시각 전에는 남은 시간, 정확한 시각에는 권장 시점, 지난 즉시 주의 색상과 경과 시간을 표시한다. 60초 미만은 ‘1분 미만 지남’, 이후 완료된 경과분이다. 실제 도착·통과·탑승 실패를 확정하지 않는다.
- 제외한 차량의 출발 권장·도착 예상·그래프와 옛 알림 안내를 제거한다. 대체 대상이 없으면 ‘이번 차량 제외됨 · 다음 차량 확인 중’이다. 제외는 30초 동안 해당 차량만 되돌릴 수 있으며 이미 실행한 알림 원장은 지우지 않는다.
- 사용자 제외로 후속 차량을 선택하면 상단·카드·타임라인·그래프의 차량 ID가 일치한다. 후속 차량의 좌석·위치는 미제공으로 표시한다. 그래프에는 그 차량의 현재 API 점 한 개와 이력 부족 안내만 둔다. 선행 차량의 모델 표본·정체 보정을 가져오지 않는다.
- 후속 예약이 3분 최신성을 넘으면 검증된 기존 예약만 ‘이전 정보 기준 예약 경고’로 유지한다. 후속 API 점의 원래 관측 시각을 유지하고 최신 보정 기호는 숨긴다. 예약 대상도 제외할 수 있다. 10분 예약 한계 등 기존 엔진 정책은 바꾸지 않았다.
- 시간대 설정만으로 후속 차량이 알림 대상이 된 경우에는 현재 차량 출발 판단을 유지하고 알림 대상 차이를 명시한다. 다른 차량의 다음 알림을 현재 차량 타임라인에 섞지 않는다.
- 출발 시각 변화 안내는 같은 차량·운행 시작·설정의 서로 다른 관측만 비교한다. 매초 감소나 설정 변경은 예측 변화로 안내하지 않는다.

## 설정·초점·알림 준비

도보와 추가 여유의 입력 초안과 적용값을 분리했다. 빈칸·범위 밖 입력은 기존 적용값을 유지하고 필드 옆 오류와 `aria-describedby`를 제공한다. change/Enter로 확정하고 스테퍼는 즉시 적용한다. 적용값·실제 다음 알림을 요약하며 저장 실패는 현재 탭에서만 적용된다고 알린다. 다른 탭의 적용값은 동기화하되 현재 편집 필드 초안을 덮어쓰지 않는다.

알림 시점·시간대·시각 알람·타이머 목록은 기존 항목과 조작 노드를 재사용한다. 매초 갱신 및 토글 뒤 초점·시간 입력 내부 편집 위치·텍스트 선택을 보존한다. 삭제 뒤 인접 조작, 항목이 없으면 추가 버튼이나 닫힌 폼의 summary로 초점을 옮긴다. 제외/되돌리기도 다음 유효 조작으로 이동한다. 마지막 요일·알림 시점을 제거할 수 없는 이유를 안내한다. 잘못된 시간대의 시작·끝 초안을 함께 수정할 수 있으며 이전 적용값은 유지한다.

상·하단에서 같은 준비 모델로 설정 켜짐·OS 권한·소리 상태를 구분한다. OS 권한 차단 시 사이트 설정과 운영체제 알림·방해 금지 설정을 안내한다. 미지원 오디오는 활성화 버튼을 비활성화하며, resume 실패·statechange·권한 변경·창 복귀를 반영한다. 권한 요청 및 OS 알림 실행 실패도 안내한다. 켜짐·권한 허용·이 브라우저의 실행 기록은 실제 전달·사용자 수신 보장이 아니다.

알림 엔진·원장·Web Locks·숨김 탭/Worker의 평가는 화면 rAF 밖에서 계속한다. 잠금 획득 시점의 최신 상태로 평가하고 화면 갱신만 모은다. 그래프는 데이터·대상·설정·보기·폭이 달라질 때 갱신하며, 같은 초당 tick에서는 DOM을 다시 만들지 않는다. 단일 polite live 영역은 의미 있는 상태 전환과 조작 결과만 알린다.

## 로딩과 새로고침

`status.json`을 먼저 적용하고 summary·CSV·운행 비교 기록은 독립적으로 읽는다. 휴일 메타데이터도 도착 시 수집 상태 표시에 반영한다. 보조 기록 로딩·부분 실패를 별도로 표시하고 기존 기록은 유지한다. 과거 전체 도착 로그는 10분마다 확인하며 같은 세대에서 중복 CSV 요청을 합친다.

진행 중인 핵심 새로고침은 같은 Promise에 합류한다. 각 요청은 body 파싱을 포함해 10초 제한시간과 AbortController를 갖는다. 세대가 지난 보조 응답은 버리고, 현재보다 오래된 관측 시각의 핵심 응답은 적용하지 않는다. 수동 조회에는 새 자료 반영·동일 자료·실패 결과를 표시한다. 실패로 마지막 정상 자료나 원래 관측 시각을 새 시각으로 바꾸지 않는다. 최초 실패에는 예정 출발을 만들지 않는다.

## 타임라인·그래프·반응형

간단 타임라인은 지금·다음 알림·출발 권장·도착 예상 최대 네 항목이다. 최초/최근 관측·조기 도착 대비 기준·이 브라우저의 알림 실행은 상세에 둔다. 채운 점은 확인된 사건, 빈 기호는 계산된 예정이다. 예정 시각이 지나도 실제 사건으로 바꾸지 않는다. `first_seen_ts`가 없으면 ‘표시 가능한 기록 시작’으로 표현하고 최근 30건을 전체 운행 이력으로 부르지 않는다.

API 이력은 차량·운행 경계를 지키며 조회 간격 2.5배(최소 3분) 이상의 공백을 잇지 않는다. 현재 보정과 조기 대비 기호는 현재 조회 한 건으로만 표시한다. 과거 모델을 소급하거나 확률 구간을 만들지 않는다. 같은 요일 비교는 KST 4주 전 날짜부터 전날까지 도착 추정 운행을 중복 제거하고 공백·추적 중단 유형은 제외한다. 실제 도착 측정이나 다음 배차 보장이 아니다.

모바일 카드는 빈자리·현재 위치 두 열과 다음 차량 전체 폭이다. 좁은 화면에서는 폼·버튼·시간대가 줄바꿈된다. 200% 확대 넘침의 원인이었던 스크린리더용 표는 별도 접근성 컨테이너로 감쌌으며 표 의미를 유지한다. 화면 전체 overflow를 숨겨 조작을 가리지 않는다. 주요 보조 정보는 14px, 주요 터치 조작은 44px 이상이다. 밝음·어두움에서 판단·준비 상태 텍스트 대비를 4.5:1 이상으로 확인했다.

## 검증과 화면 증거

- Node **83/83**: 기존 알림·안전 정책과 표시 함수. 출발 경계·제외·후속 예약 만료·차량 그래프·모델 분리 포함.
- Python 통합 **106/106**(Node 실행 래퍼 포함), 이 중 실제 Chromium **30/30**. 10초 timeout·핵심 요청 합류·이전 세대 무시·새/동일/실패 안내·초점·선택 범위·저장 실패·권한/오디오·다중 탭 설정·시각 알람/타이머를 검증한다.
- 360/390/1280px, 밝음/어두움, 감소 동작 및 각 폭의 CSS 200% 확대에서 펼친 폼·기록 표·버튼의 가로 넘침을 확인했다. 키보드 토글·삭제·필드 오류·접근성 표 역할·핵심 텍스트 대비·단일 live 영역도 검사한다.
- `git diff --check`, `bash -n bus-arrival/scripts/session.sh` 통과. Windows subprocess의 CRLF 문제는 Bash 입력을 UTF-8 bytes로 전달하도록 테스트 하네스만 수정했다. 테스트 삭제/skip이나 세션 스크립트 변경은 하지 않았다.
